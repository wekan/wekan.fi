Details

OidcRaceBleed — CWE-362 Race Condition → Account Takeover

With OIDC login enabled, packages/wekan-oidc/oidc_server.js declared the request-scoped profile, serviceData and userinfo objects at module scope. The OAuth callback writes to them and awaits the token, userinfo, configuration, group and board mapping requests, so another login could run during those awaits and overwrite the same serviceData. serviceData.id is the field Meteor's OAuth account matching uses: when login A finished after login B had overwritten it, A's credential was stored with B's OIDC subject and A received B's WeKan account.

The same shared state also leaked fields between consecutive logins and, with PROPAGATE_OIDC_DATA, could write one user's email, teams and admin flag onto another user's document - the "web interface shows different data than the database" report of #4897. All login state is now local to each login, and tests/oidcLoginStateIsolation.test.cjs proves concurrent logins stay isolated and fails on the code before the fix. Fixed in WeKan v9.97 on 2026-07-17.

Reported privately by meifukun (https://github.com/meifukun), who reviewed 8 issues against WeKan v9.95.0 (commit f602b9459fa1622f60ee8c3b639f02035f3ab32b) on local self-hosted instances only, and later submitted as GHSA-6944-p22h-3qpx. When the report arrived, the race was already fixed by #4897; a source guard keeps it fixed.

Nothing is shown in Admin Panel → Problems for this one: the fix refuses nothing, it keeps every legitimate login's data apart.
