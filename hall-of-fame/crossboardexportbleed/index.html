CrossBoardExportBleed 2026-11-01 ccsimplyspolit

Reported privately by ccsimplyspolit through GitHub Security Advisory GHSA-8885-xrq4-j47h, with details, verification code and a suggested fix for both findings; validated and fixed by xet7.

A board export scoped with ?checklistId= streamed a checklist of another board - a private one too - with its items and its creator. The streaming CSV/TSV export ignored Disable all export and Anonymize export users, and so did the Excel, PDF, chart, calendar and external-format exports.

Details

Finding 1. GET /api/boards/:boardId/export?checklistId=... and exportZip chose the cards to export with the board's id, but selected the scoped checklist and its items by the checklist's id alone. A checklist on a card of another board matched no card of the exported board, yet it was still streamed, with every item and its creator's user record, whose profile the anonymization map did not cover. Anyone who could export one board - or anyone at all, through a public board - could read a private board's checklist whose id they knew.

Finding 2. Admin Panel / Features / Security promises that with Disable all export "the server rejects any export request", and that Anonymize export users leaves no real identity in an exported file. Only the WeKan JSON, ZIP and Trello exports asked. The streaming CSV/TSV export the report names did not, and neither did the Excel (board, card, all boards), PDF (board, card), chart, calendar and external-format exports.

Fix: both checklist selectors are bound to the exported board's cards. Every HTTP export route answers 403 before writing anything when export is disabled (refuseDisabledExport), and every exporter that names people anonymizes users, mentions, requested-by / assigned-by and comments with the same map the JSON export builds (anonymizeExportIdentities).

Detection

A checklist scope from another board is recorded in Admin Panel / Problems as CrossBoardExportBleed (key authz.export-checklist-scope): no export menu asks for one. An export while all export is disabled is recorded too (authz.export-disabled), without blocking the account, because a page opened before the switch still shows the menus. An anonymization leak is in what a response carried, so it has no event of its own.

Verification

tests/crossBoardExportBleed.test.cjs drives the gate and the anonymizer, and scans the tree: no scoped checklist is selected by id alone, no export route lacks the gate, and no exporter that names people skips anonymization; all of it fails on the code before. tests/playwright/specs/security-cross-board-export.e2e.js replays the reporter's requests against a running server.
